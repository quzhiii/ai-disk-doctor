# UX Direction

## UX Goal

Product decision: AI Disk Doctor should feel like a calm system utility for AI-era computing. The product identity should come from semantic understanding and safety, not decorative AI visuals.

Prefer:

- calm system-level visual language
- high information clarity
- strong hierarchy
- restrained motion
- clear risk states
- visible provenance and evidence
- progressive disclosure

Avoid:

- generic robot or AI-brain imagery
- unexplained technical jargon
- color-only risk communication
- over-promising safe cleanup based only on size

## Future Desktop Information Architecture

### Overview

First answer:

- total AI/developer footprint
- actionable reclaim estimate
- review-required storage
- protected or recovery-critical storage
- recent growth
- top growth sources
- primary scan action

### Clean

Human review flow:

- selectable candidates
- risk and recovery labels
- expected reclaim
- why explanation
- action mechanism
- explicit confirmation
- quarantine-first behavior

### AI Assets

Unified view of:

- models
- agents
- AI IDEs
- runtimes and containers
- project artifacts

### Recovery

Project-oriented coverage:

- Git
- Agent snapshots/checkpoints
- sessions where relevant
- AI Disk Doctor quarantine
- most recent recovery evidence
- storage consumed by recovery assets

MVP is inventory and explanation. It is not a backup engine.

### Activity

Timeline derived from:

- scans
- diffs
- anomalies
- clean/quarantine operations
- restores
- future monitoring events

## Safety UX States

Recommended conceptual states:

- SAFE / RECLAIMABLE
- REVIEW
- PROTECTED
- REPORT ONLY
- OFFICIAL TOOL
- PARTIAL / UNKNOWN

Product decision: every unfamiliar item should support beginner-first answers: what it is, why it exists, why it is shown, whether it can be removed, what happens if removed, how recovery works, and why the recommendation is trustworthy.
