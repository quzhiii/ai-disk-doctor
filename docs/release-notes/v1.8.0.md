# AI Disk Doctor v1.8.0

v1.8.0 is a Core Agent-Alpha release candidate based on accepted Core master `20d90a3febe63607112b920f48d1e3ca3cdaa6ca`. It creates a real downloadable runtime baseline for Integration I3 without adding product features or changing scanner, risk, cleanup, quarantine, restore, or action semantics.

## Release Decision

- Version decision: next minor release `v1.8.0`, because SemVer-style repo history uses additive capability releases and the Agent diagnostic CLI was added after the published v1.7.0 artifact.
- I3 runtime baseline: `cac502f73c39f1b5de13bab3e4de86a5c29684fc` is included in current master and this release candidate.
- Old release boundary: published v1.7.0 is `fd6eb72a053b6da6f13a14f9c085e40f7deb9264` and must not be treated as the new Alpha runtime artifact.
- Publication gate: Do not tag or publish v1.8.0 until Owner Acceptance approves this release candidate.

## What Changed

- Release candidate now includes `agent-capabilities-v1` through `aidisk capabilities --json`.
- Release candidate now includes `agent-diagnostic-cli-v1` through `aidisk explain --json --snapshot skip`.
- The Agent diagnostic envelope embeds the unchanged `explainability-v1` evidence contract.
- The accepted P1 shared-root traversal performance fix is included; see `docs/performance/p1-shared-root-traversal.md`.
- Release/package smoke now validates packaged binary support for `aidisk capabilities --json`, `agent-diagnostic-cli-v1`, snapshot `skip`, and embedded `explainability-v1`.
- The existing six-target release workflow is retained with archive packaging, SHA-256 checksum sidecars, Cargo metadata SBOM, provenance JSON, package smoke, built-in `rules/`, default `config/`, and `Start-AIDiskDoctor.ps1`.

## Contract Evidence

- `agent-capabilities-v1`: `aidisk capabilities --json` returns one JSON document and does not create `.aidisk` scan history.
- `agent-diagnostic-cli-v1`: `aidisk explain --json --snapshot skip` returns one JSON document with `snapshot.persisted = false`.
- `explainability-v1`: the diagnostic payload delegates to the existing Core explainability boundary rather than reconstructing risk, handling, provenance, recovery, or path evidence.
- Package smoke: `.github/workflows/release-artifacts.yml` runs the same contract checks against the extracted artifact before upload.

## Performance Evidence

- P1 shared-root traversal is included in master commit `20d90a3febe63607112b920f48d1e3ca3cdaa6ca`.
- Performance evidence reports median complete `aidisk explain --json --snapshot skip` after P1 at `43.577s`, below the `60s` strong-pass threshold and below the Integration `120s` timeout.
- Traversal regression tests prove repeated recursive patterns sharing one root enumerate that root once while preserving findings, accounting, risk, action, and partial state.

## Safety Boundaries

- No release tag or GitHub Release is published by this release-readiness PR.
- No Integration PR, Desktop repo, scanner semantics, risk model, cleanup planner, quarantine execution, restore behavior, or action proposal semantics are changed.
- The Agent diagnostic CLI remains read-only; `--snapshot skip` avoids writing scan history and does not execute cleanup or shell commands.
- P1 changes traversal reuse only; it does not canonical-dedupe, prune reparse points, change byte accounting, or alter action eligibility.

## Known Limits

- v1.8.0 artifacts are release-candidate outputs until Owner Acceptance approves tagging and publication.
- Windows ARM64 package smoke still verifies archive contents on the x64 Windows runner and skips binary execution, matching the existing release workflow convention.
- SBOM remains Cargo metadata format; richer signed SBOM/provenance is deferred.
